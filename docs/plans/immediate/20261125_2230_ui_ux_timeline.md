# Plan: UI/UX — fix page bugs, make the timeline the main view

**Status**: OPEN
**Created**: 2026-11-25

## Thought Process & Context
The page was opened on real session `01a20417-4c90-7660-8277-d549fb426160` (29 turns, 20 LLM nodes) at 1365x768. Observed:

1. On open the graph is a thin strip of unreadable cards (zoom clamped at 0.25) and still runs off the right edge.
2. "Fit" does not fit: the graph stays cut off on both sides.
3. At 100% the first card sits under the left sidebar: `#world` paints outside `#viewport`.
4. After pressing "100%" or "Fit" the bottom toolbar `#bar` slides left and is clipped ("Chosen path only" loses its first letters). `#viewport` appears to scroll.
5. The page opens on noise: Follow selects the latest node, which was a `side` node ("Lone 'h' message").
6. "Chosen path only" only dims cards; the row stays as long.
7. Edge labels are cut off by the cards.
8. The left sidebar lists (chosen outcomes, rejected paths) and the right inspector are the readable parts. The one-row graph is the weakest part.

Decision: a top-to-bottom timeline becomes the default view. The graph stays as a second tab and gets its bugs fixed.

## Files
Owned by this plan: `web/index.html`, `web/app.ts`, `web/view.ts`, `web/layout.ts`, `web/style.css`, `test/view.test.ts`, `test/layout.test.ts`.
Do not touch `src/` (other work is in flight there). `src/model.ts` types stay as they are.

## Phases

### Phase 1: Graph view bugs
**Status**: OPEN
- `#viewport` must clip its content (`overflow: hidden`, own stacking context) and never scroll; `#world` never paints over `#sidebar`/`#panel`; `#bar` stays centred in the viewport after every button.
- `fitView` uses the viewport's real client size and the real node bounds (`NODE_W`/`NODE_H`), with padding. When the whole graph would need zoom below a readable floor (0.6), do not shrink further: zoom to the floor and centre on the selected node instead.
- Edge labels are not hidden by cards (place them in the gap or draw them above the cards with a background).
- Filters hide instead of dim: with "Chosen path only" or "Decisions & Rejections" the filtered-out nodes and their edges are removed and the layout is recomputed on the remaining nodes (bridge the spine across removed nodes so the row stays connected).

### Phase 2: Timeline view (new default)
**Status**: OPEN
- Add a view switch in `#bar`: "Timeline" (default) and "Graph". Persist the choice in `localStorage`.
- Timeline: one vertical, scrollable column in `#viewport`, ordered as the spine runs (goal first). Spine nodes (`goal`, `decision`, `chosen`, `loop`) are full-width rows. `rejected`, `option` and `side` nodes are smaller indented rows under the spine node they branch from (edge `from`), with the edge label shown.
- Row content: badge, title, desc, turn count and time. `loop` rows show the round count prominently. Rejected rows show the rationale inline ("why rejected").
- Clicking a row selects the node (same inspector as today). Keyboard: Up/Down moves the selection, in both views.
- The timeline needs no pan/zoom; "Fit" and "100%" are hidden in that view.
- Order comes from a pure exported function in `web/layout.ts` (e.g. `timelineRows(nodes, edges)`) so it is unit-testable; nodes unreachable from the goal are appended at the end, never dropped.

### Phase 3: Open on signal, fewer colours
**Status**: OPEN
- Follow selects the latest spine node (`goal`/`decision`/`chosen`/`loop`), never a `side` or `option` node. Fallback to the latest node only when no spine node exists.
- Top of the timeline: a three-line summary — Goal (goal node title), Now (latest `chosen` node title, else latest spine node), Rejected (count; clicking scrolls to the first).
- Legend and palette reduce to three groups: chosen (goal/chosen), rejected (rejected/option), other (decision/loop/side). Kinds remain distinguishable by badge text.
- The "N turns → M nodes" pill stays.

### Phase 4: Tests
**Status**: OPEN
- `test/layout.test.ts`: `timelineRows` order for a spine with rejected/side branches; unreachable nodes kept; filtered layout has no gaps.
- `test/view.test.ts`: follow target skips side/option nodes; `fitView` result keeps zoom >= floor and puts the selected node inside the viewport; filters remove nodes.
- `bun test` and `bun run typecheck` pass.
